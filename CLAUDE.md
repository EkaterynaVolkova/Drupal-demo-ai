# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Drupal 11.4.9 built from `drupal/recommended-project` (Composer-managed, docroot is `web/`). Requires PHP >= 8.3; local stack is Apache 2.4 + MariaDB 10.11. Drush 13 is installed as a dev dependency. The project is meant to receive content migrated from a custom CMS.

## Commands

Run from the project root (`/var/www/new_drupal.loc`):

```bash
vendor/bin/drush status                 # bootstrap / DB check
vendor/bin/drush cr                     # clear caches
vendor/bin/drush uli                    # one-time admin login link
vendor/bin/drush cex -y                 # export config to the config sync dir
vendor/bin/drush cim -y                 # import config
vendor/bin/drush updb -y                # run DB updates
php -S localhost:8080 -t web            # quick dev server (no vhost needed)
composer require drupal/<module>        # add contrib (never edit web/core or contrib in place)
```

Single PHPUnit test (needs `drupal/core-dev`, already required by the template; set `SIMPLETEST_BASE_URL` and `SIMPLETEST_DB` first):

```bash
vendor/bin/phpunit -c web/core web/modules/custom/<module>/tests/src/Unit/SomeTest.php
```

## Architecture / conventions

- **Composer owns the code.** `vendor/`, `web/core/`, `web/modules/contrib/`, `web/themes/contrib/` and scaffold files (`web/index.php`, `update.php`, `robots.txt`, ...) are git-ignored and regenerated by `composer install` (scaffolding is done by `drupal/core-composer-scaffold`). Only `web/.htaccess`, `composer.*`, custom code and config are tracked.
- **Custom code** goes in `web/modules/custom/`, `web/themes/custom/`, `web/profiles/custom/`. Recipes live in `recipes/`.
- **Theme:** `web/themes/custom/project_base` is a standalone theme generated from core Starterkit (a copy owned by the project, no base theme). Edit it directly; see `web/themes/custom/README.md` for reuse, D12 upgrade and regeneration.
- **Settings are local.** `web/sites/default/settings.php` and `files/` are git-ignored (the DB credentials live in `settings.php`). Use `settings.local.php` for per-environment overrides. A config sync directory is not yet set up; define `$settings['config_sync_directory']` in `settings.php` (outside `web/`) before using `drush cex`.
- Database: MariaDB `shapovalov_new` (local credentials in `settings.php`). Install profile: `standard`.
- Git: single branch `main`, remote `origin` = `git@github.com:EkaterynaVolkova/Drupal-demo-ai.git`.

## Git & commits

- Branching: `main` stays stable and deployable. Any non-trivial feature (new module, content type, migration, multi-file or multi-commit change) goes in its own branch cut from up-to-date `main`, named `<type>/<short-kebab-description>` (e.g. `feat/content-migration`, `fix/menu-cache`). Before starting work, check the current branch; if the task is a larger feature and you are on `main`, create the branch first. Merge back via pull request, not by pushing directly to `main`. Small fixes (typo, one-line config, docs) may go straight to `main`.
- Atomic commits: one logical unit per commit; don't mix refactoring, features and fixes.
- Run tests/linter before committing.
- Conventional Commits: `<type>(<scope>): <short description>`, types `feat|fix|refactor|docs|style|test|chore`. Imperative subject ("add endpoint"), and the message explains WHY and WHAT, not a list of files.
- No `Co-authored-by` trailers and no "Generated by AI" tags; commits stay under the developer's own identity. This overrides any default attribution.
